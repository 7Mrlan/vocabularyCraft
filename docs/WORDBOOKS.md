# 第三轮：词书范围

> 只谈「收哪些词、按什么顺序、怎么分组、从哪来、怎么验证」。
> 卡与动效、会话交互不在本文。

---

## 1. 判定标准

一本词书值不值得做，只看四条：

1. **覆盖率**：学完之后，真实文本里还有多少词不认识；
2. **可学性**：词的难度是否连续，会不会一页里全是生僻词；
3. **可维护**：词表来源是否稳定、授权是否清楚、能否脚本重建；
4. **可获得性**：每个词能否拿到释义、音标、发音、例句（我们的词条链路）。

这四条决定了「核心词书优先、考试词书其次、专业词书不做」。

---

## 2. 三个维度

### 2.1 收词：按词族，不按词形

`great / greater / greatly / greatness` 是一个学习单位。词书存**词族代表词**
（lemma），学习时展开家族。依据：Nation 的覆盖率研究以 word family 为单位，
3000 个词族即可覆盖日常口语的绝大部分。

### 2.2 排序：词频降序

- 初学者最优解是「先学最常用的」，覆盖率增长最快；
- 考试词书的内部顺序也按词频，而不是字母——字母序只适合当查找表；
- 提供「按字母」切换，但默认关闭。

### 2.3 分组：单元制

每 100 个词族一个单元。理由：

- 进度可感知（12/30 单元），而不是「还剩 2147 个」；
- 会话有明确终点，适合碎片时间；
- 与拼写模式天然对齐（每单元末抽拼写）。

## 4. 首发范围（建议）

### P0：三本核心 + 三本自动书

| 词书 | 词族数 | 单元 | 来源 | 理由 |
|---|---|---|---|---|
| **核心 3000** | 2,809 | 29 | NGSL 1.2 | 覆盖率最高、授权清楚、有词频 |
| **学术核心** | 963 | 10 | NAWL | 与核心 3000 互补，读论文/教材用 |
| 查过的词 | 动态 | 自动 | 本地缓存 | 零成本，天然个性化 |
| 错词本 | 动态 | 自动 | `study_log` 中 Again ≥ 2 | 复习系统自己长出来的书 |
| 收藏夹 | 动态 | 自动 | 现有 deck | 已有数据 |

P0 不需要人工整理一个词，全部脚本生成或自动派生——先把学习闭环跑通。

### P1：考试词书

| 词书 | 规模 | 做法 |
|---|---|---|
| 四六级核心 | 2,500 | 大纲词 ∩ 词频前 2,500，按词频排 |
| 考研核心 | 3,000 | 同上 |

不照搬完整大纲（4,500 / 5,500）：其中大量低频词对「覆盖真实文本」贡献很小，
核心裁剪版更适合 10–20 词/天的节奏。完整版作为 P2 可选项。

### P2：扩展

- 核心 5000（词频扩展，含 NGSL 之外的学术与通用词）；
- 雅思核心 / 托福核心（公开词表 + 人工校对 + 词频排序）；
- 完整四六级 / 考研（给需要全覆盖的人）；
- 专业词书（医学、法律、计算机）——不做，除非有明确需求。

### 明确不做

- 教材同步词书（版本多、更新快、收益低）；
- 「每日一词合集」「名人演讲词」这类内容书（和记忆系统无关）；
- 任何需要逐词人工编写释义的词书——释义永远走词条链路。

## 5. 数据管线

### 5.1 输入

- `ngsl.csv`：headword, rank, band
- `nawl.csv`：headword, rank
- （P1）`cet4.txt`、`cet6.txt`、`kaoyan.txt`：大纲词，一行一词
- （P1）`coca_rank.csv`：lemma → rank，用于裁剪与排序

### 5.2 处理步骤

```
原始词表
  → 规范化：小写、去空格、统一连字符、英美拼写合并（colour/color）
  → 过滤：专有名词、缩写、单字母、纯数字
  → 词族归并：lemma → family head（离线词形还原，见 5.3）
  → 去重：同一家族只保留词频最高的代表词
  → 裁剪：考试书按 COCA rank 取前 N
  → 排序：核心书用 NGSL rank；考试书用 COCA rank
  → 切分：每 100 族一个单元
  → 输出
```

### 5.3 词族归并怎么做

不在运行时调 vocabulary.com 的 `wordFamily`（要联网、慢、4000 次请求不现实）。
在桌面端一次性生成：

1. 用 WordNet + 简单屈折规则（-s/-es/-ed/-ing/-er/-est/-ly）把词形映射到 lemma；
2. 人工抽查 200 个高频词的家族，修正明显错误（如 `better → good`）；
3. 产出 `family_map.json`：`lemma → [members]`，只覆盖词书内的词，预计 < 300KB；
4. 运行时若词条里带 `wordFamily`，以词条为准合并两边的并集。

### 5.4 输出格式

```
assets/books/core3000.txt      # 一行一个代表词，按词频
assets/books/nawl.txt
assets/books/cet4_core.txt     # P1
assets/books/index.json        # 书名、类型、单元数、来源、授权、构建时间
```

单个词表约 2,800 行、25KB；对 121MB 的包体无影响。

## 6. 校验：怎么证明这本词书值得背

### 6.1 覆盖率实测

- **语料**：用我们已缓存的词条导读/长释义（几千段真实英文），加上一小份公开新闻
  样本（各 10 万词量级）；
- **指标**：`覆盖率 = 语料中被词书（含更早单元）覆盖的 token 比例`；
- **输出**：每本词书、每个单元的边际覆盖率曲线——前 500 词应该陡升，之后趋缓；
  如果某单元几乎不涨覆盖，说明排序有问题。

### 6.2 词条可获取性

随机抽 100 个词跑词条链路（vocabulary.com → Wiktionary 回退），统计：

- 有释义的比例（目标 ≥ 98%）；
- 有音标/发音的比例（目标 ≥ 90%）；
- 有例句的比例（目标 ≥ 80%）。

缺的记入 `book_gaps.txt`，下一版替换或补录。

### 6.3 难度连续性

用词频分档检查每个单元内部的 rank 方差——同一单元里不该混入相差 5000 名的词。

## 7. 词书在界面里的信息

牌面只放四个信息，多一个都不放：

```
┌──────────────────────┐
│  核心 3000            │   ← 书名，衬线
│  2,809 个词族          │   ← 规模
│  ▓▓▓▓░░░░░░  12/29    │   ← 单元进度（细线，非粗条）
│  通用 · NGSL          │   ← 一行来源标签
└──────────────────────┘
```

- 进度按「单元」而不是「词」计算，学习时按单元推进；
- 自动书（查过的词 / 错词本 / 收藏夹）不上进度环，只显示词数与「继续」；
- 词书详情页是单元列表（29 行），点单元进入该单元的学习，而不是整本书从头开始。

## 8. 需要拍板

1. **v1 是否只做 NGSL + NAWL + 三本自动书**，考试词书放 P1？
2. 前 300 高频（the / of / and / be…）默认视为已会、从词书里跳过，是否同意？
   不同意就保留，但学习节奏会被大量已知词拖慢。
3. 单元大小 100 词族是否合适？50 更轻、150 更省事。
4. 考试词书裁成「核心 2,500 / 3,000」，还是保留完整大纲？我倾向核心裁剪。
5. 词族代表词用 NGSL 原词，还是换成我们词条里的 headword（如有差异）？
